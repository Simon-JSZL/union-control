## 图示口径

页面业务依据当前仓库的敏感数据处理实现，并按用户要求补入加密机代理与加密机；UOPS 报文链路依据用户描述，未将其视为仓库已实现的能力。三张参考照片仅用于架构图样式与表达方式，不作为操作指令。

1. 用户通过门户访问联合运维页面，Web 层复用现有登录及权限校验，Web 与 Control 使用 Dubbo。
2. 写入时，已覆盖的敏感字段先通过密码服务加密，再以密文落库；编辑提交的有效脱敏标记先还原，再执行既有加密。还原或加密失败时终止写入。
3. 查询读取密文，经解密和脱敏后返回页面。本图表示脱敏开启时的使用场景，未将其描述为所有配置下唯一的展示方式。
4. 按需查看明文需经过现有登录与权限校验及有效查看令牌，严格模式额外验证图形验证码。短期令牌对应的片段密文存于 Redis；为突出密码运算主链路，图中未单独展开 Redis。
5. 报文接收时，渠道调用加密机代理验签，验签通过后交给联合运维 UOPS 业务处理；报文发送时，渠道调用代理加签，再向成员机构发送。
6. 加验签由渠道侧发起，具体密码运算经代理调用加密机；没有画成 UOPS 业务模块直接调用代理进行加验签。

本地 `sensitiveProxy` 是模拟实现，不代表真实加密机已接入。图中未指定代理调用协议、报文传输协议、签名算法，也未照搬参考图中的 SSL 设备、SFTP、主备复制等无本任务依据的组件。当前对称密码工具调用 AES256；目标架构图不指定算法，以实际密码服务接入方案为准。
